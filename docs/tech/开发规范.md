# 开发规范

> 维护人：王码（主程）
> 版本：v0.1（D2）

## 代码规范

### GDScript 4.3

- 缩进：Tab
- 类型标注：强制
- 命名：变量/函数 `snake_case`，类/信号 `PascalCase`/`snake_case`，常量 `UPPER_SNAKE_CASE`
- 每文件头注明：用途 + 维护人 + 版本
- 导出变量加 `@export` + 取值范围注释

### 场景命名

- 场景文件：`PascalCase.tscn`（如 `MainMenu.tscn`）
- 场景内节点：`PascalCase`
- 目录：小写短横线（如 `ui/h-event/`）

## Git 规范

### 分支

```
main      稳定
dev       集成
feature/* 功能
fix/*     修复
hotfix/*  紧急修复
```

### Commit 格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

**type**：feat / fix / refactor / docs / test / chore / perf / build / ci / revert

**示例**：
- `feat(battle): implement turn order calculation`
- `fix(save): correct version migration for affection dict`
- `docs(gdd): update H event threshold`
- `ci(android): add gradle build step`

### PR 审查清单

- [ ] 单元测试通过（本地跑一次）
- [ ] 冒烟测试通过（如涉及启动/存档/战斗/H 事件）
- [ ] 数值 clamp 到位
- [ ] 存档字段兼容旧版本
- [ ] 无硬编码 API Key/路径
- [ ] 命名符合规范
- [ ] PR 描述包含：变更内容 + 测试结果 + 相关 KN/TC 编号

## 敏感信息

- API Key、Keystore、密码：**禁止入 Git**
- 用 `.env` 本地文件 + CI Secrets
- `.gitignore` 已配置

## 构建流程

1. `dev` 分支合并 PR → CI 触发 Windows + Android + Web 三平台构建
2. 构建产物上传 GitHub Actions artifact
3. 通过冒烟 + 单测后，`dev` → `main` 合并 → 发布 tag
4. 发布 tag 触发正式发布流程

## 备份与回滚

- 每日 02:00 自动备份整个 `开发项目/` 到 `.backup/`
- 每月 1 次恢复演练
- 回滚：`git revert <commit>` 优先，不用 `reset`

## 代码审查 SLA

- PR 提交后 **24h 内** 至少 1 人 review
- P0 修复 PR 当日合并

## 二、✅ runner 执行语义 bug（v0.3 已修，2024-11-19）

**原问题**：`expand_entries` 把 `count=N` 展开成 N 个 item，**每个 item 都 build_cmd 同一条命令** → 168 条 hook 跑 168 次命令，实际唯一执行体仅 15 个。

| 执行体 | v0.2 重复次数 | v0.3 实际跑 |
|---|---|---|
| gd:test_save_portrait | 23 次 | 1 次 |
| gallery_check | 18 次 | 1 次 |
| asset_3d | 16 次 | 1 次 |
| mixed | 15 次 | 1 次 |
| gd:test_ch5_boss | 13 次 | 1 次 |
| lint | 12 次 | 1 次 |
| smoke | 11 次 | 1 次 |
| …其余 8 个 | 各 1-10 次 | 各 1 次 |

**修复内容（王码 v0.3）**：
1. ✅ `expand_entries` 按 exec **去重**——每个唯一执行体跑 1 次，`covered_count` 累计覆盖条数
2. ✅ JSON 拆字段：`exec_count`（执行体数）/ `covered_count`（覆盖用例数）分开报
3. ✅ 15min 对账用执行体耗时，覆盖条数单列
4. ✅ 补 `mixed` 执行体注册（TC-V12 存量，复用 lint.py）

**验证结果（王码，GODOT_BIN=echo mock）**：
- dry-run：P0 53→**6** 执行体 / P1 34→**3** / P2 61→**5** / P3 20→**2**，跨组唯一条目 **16**
- 说明：15 个 exec 类型 + mixed 补注册后 16 条目；其中 mixed→lint.py 与 lint→lint.py 命令相同，实际启动 **15 种命令**（与 v0.2 统计口径一致）
- P0 分片实测：执行体 3 / 覆盖 22 条 / 0.08s，JSON 拆分正确 ✅
- 全局 `--all`：执行体 16 / 覆盖 168 条 / 挂接率 100% ✅
- mock 下 P2 三红（check_3d_assets / check_gallery --strict / lint）系**本地无 LFS 实物 + 资产未就绪的预期红**，非脚本 bug——strict 拦红正是验收红线要的效果；接 CI 拉全 LFS 后应由绿
